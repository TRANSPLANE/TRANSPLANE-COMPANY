# TransPlane Company

English entry instructions: [references/entry.en.md](references/entry.en.md). Read them when operating for an English-speaking user. CLI uses global `--lang en|zh-CN`; HTTP uses `Accept-Language` or explicit `lang`, with the query taking precedence. Stored company content remains unchanged.

先确定用户选择的部署入口、公司及接入方式。入口来自用户或当前工作区配置，不扫描其他机器和服务。凭据使用用户已经授权的安全存储，不写入公司资料、报告或公开文件。

接入成功后，将不含凭据的部署入口、公司标识及适用的本地 CLI 路径保存到当前 Agent 已获准使用的工作记忆或安装后的 Skill 引用文件。后续维护复用该选择；入口、公司或授权发生变化时重新核对。

每次玩家回复前，必须读取并应用入口的 `player_output.policy` 或本次 `play` 的 `player_output_policy` 完整呈现合同，包括布局、规则及发送前检查；它是默认叙事合同，不是可选参考。旧部署没有完整内嵌合同时，再读取入口的 `player_output.guide` 或 `/api/v1/agent-guide?topic=player-output`。按场景、人物台词、结果和下一选择组织回复，省略无内容的部分。操作合同、回执、版本及工具过程留在后台；关键未知、风险和未完成状态如实保留，详细依据按请求展开。

模拟中反复出场的主要人物采用稳定自然名或已知角色称谓，延续身份、诉求和承诺；即使旧报告和当前事件仍写 V5 等研究样本号，也不能照抄到玩家文字、在人名旁附旧号或宣布改名。优先复用公司人物资料，缺少称呼时按合同接续并保存获准映射，保留原标识和历史；真实人物仅用实际或获准称呼。表达改变不改变选择内容，按当前 `option_id` 映射提交。

首次部署后给出登录入口与下一步：新建真实或模拟公司，确认起步方向，再准备第一幕。界面已建档时接续其公司标识，避免重复创建。新开局先建立可理解的结果目标与路线，保存一个自足事件，随后等待玩家选择；可以全程在对话中进行。

## 按任务发现能力

无需在本地安装经营 Skills。当前部署的 `agent-entry.skills` 给出内置模板、公司目录和维护引导；先读轻量名称与用途，只展开当前任务相关正文。公司文档使用当前公司授权；内置和插件文档可复制为独立公司规范。只应用启用、有效且适用于该公司模式的 Skill，文档不替代操作合同，也不授予新的权限。

用户要求总结长期经验时，按 `skill.put` 合同保存有适用条件、做法、来源、例外和复核条件的规范，关联已有证据的精确版本。远程维护需明确 `skills.write`，普通经营写入权限不包含它。用户未要求时将结论留在报告中；不从单次模拟结果推断真实市场规律，不把秘密或访问凭据写入 Skill。

本地运行 `company --data-dir <数据目录> discover`，网络读取 `GET /api/v1/agent-entry`。首次只读取建档所需能力；按当前任务从 `/api/v1/discovery` 读取服务、操作及精确合同，再从 `/api/v1/agent-guide?topic=...` 读取维护引导。以当前部署返回的合同为准，插件安装后再发现其能力。

公司资料从该公司的 `INDEX.md` 开始，按关联读取需要的文件。先读取公司 `mode`：真实经营依据实际记录；模拟公司的资源、行动和结果明确保持虚构，不混入真实公司。经营判断依据记录、用户目标和已确认约束；缺少实际经营数据或无法核对的现实事实时保留未知，向用户索取所需实际资料或最小必要的数据来源授权。模拟背景的缺失按主持规则补充明确虚构情景。采用经营结果和里程碑表达成长目标，具体执行步骤由客户端管理。

主要交互发生在用户自己的 Agent 对话中，用户可以全程文字游玩。前端辅助可视化、查看和按需分享进度截图、访问服务模块与管理部署，也保留直接选择功能。读取 `company.play` 合同，通过 `company play --company <id>` 或 `GET /api/v1/companies/<id>/play` 取得当前事件、完整方案文字、保存意向、处理阶段、固定历史结果、资金与目标及页面链接。呈现处境和经营方案；用户说出方案文字或标识时，用当前决策版本保存选择，不要求先打开页面。自由方案只在事件允许时提交；无法唯一识别的表达先澄清，不猜测相似选项。

玩家说“继续”时，先重读 `play`：未选择则给出方案；已选择未领取则领取并处理；处理中则核对领取者和结果，避免重复执行；已结算则展示结果并准备下一事件。不能将一次“继续”解释为替玩家选择尚未选定的经营方向。

查看状态、路线、菜单或报告时，读取 `company.presentation` 和需要的公司模块。使用返回的 `/?company=<id>#<view>` 生成所选部署的快捷访问链接，链接不含凭据。部署已配置截图服务时，按 `company.capture` 合同请求实际前端模块截图并展示给用户，同时附结构化状态及链接；截图未配置或失败时，展示返回的状态与链接，不伪造截图，也不把不可用截图作为继续游玩的前提。

真实公司使用用户提供的实际资源、客户及经营记录。模拟公司由 Agent 担任主持人，可以主动设计明确虚构的公司背景、产品、客户画像、事件及客户响应假设，沿用玩家已确认的世界设定；缺少虚构背景时补充自洽的情景，不要求玩家认识现实客户或每回合补齐世界细节。只在经营方向、授权、资源约束等会改变玩家选择的问题上澄清。每个方案应给出行动、对象和承诺范围，足以按所选方案推进。

为经营判断读取相关公司资料；需要现实行业、价格、需求或成本事实时核对外部资料，记录来源 URL、观察日期、事实、情景假设及计算过程。虚构客户响应和假设收益标明为模拟结果，不冒充现实市场证据；没有可靠现实依据时保留未知或明确采用情景假设，不因模拟公司没有实际客户而中断游戏。

真实公司计算缺少必要依据时，索取实际资料或获取数据所需的最小授权与连接凭据，不以虚构数据代替实际资金和客户。秘密只进入用户 Agent 的安全凭据存储或专用配置，不写入公司资料、报告、经营导出和截图。截图与进度仅按请求返回，外部分享和发布仍需用户明确授权。

## 主持经营事件

先查询当前公司是否存在未结束的经营决策，以及其基线、版本和已保存选择。每家公司同时最多一个未结束事件；没有事件时，依据当前处境和经营目标设计下一项有意义的取舍，按当前部署发现的决策合同提交。方案表达经营结果、预计代价和风险，不写成工具执行清单；假设花费不得伪装成已发生支出。

玩家选择只保存意向，不扣款、不推进经营指标，也不授予外部行动权限。主人或已获该公司 `company.write` 权限的 Agent 可以通过 `decision.select` 保存意向；只读凭据不能选择。`choice` 可以使用当前方案的精确标题或标识；已有保存意向且尚未领取时，可以使用最新决策版本重新选择。界面复制的交接文本仍需用户发送给自己的 Agent；读取部署中的保存意向后才能称已收到。Agent 使用 `decision.claim` 领取处理后方案固定；改变处理中方案时先协调停止、取消旧事件并保留历史，再准备新事件。

处理前用当前版本领取事件，再读取服务中最新保存的意向和领取回执，以其选择为准。核对相关经营记录、市场依据和外部权限。相关经营资源在事件准备后改变时，按冲突提示读取最新数据并修订；普通报告或未关联资料变化不要求重新维护事件。决策自身更新使用 `expected_revision`。执行获准的现实行动或明确虚构的模拟行动，通过共享接口提交账目、客户、订阅及目标等结果；操作成功后发布模拟回合或真实经营报告，以 `decision.resolve` 关联同公司精确记录标识及版本。结果引用已提交记录，不用未入账叙事宣称结算成功。结束当前事件后再准备下一事件。

历史结果的引用版本保持固定。后续账目或报告更正不覆盖旧结果的依据；需要修订时保存新版本并说明其经营意义。界面显示等待时，不把尚未运行的行动说成成功或失败。平台不生成剧情、不自行推理、不唤醒 Agent。

## 写入与核对

- 结构化记录通过 CLI、文件导入或 API 提交；数据库是主账，不直接修改数据库文件。
- 修改已有记录前读取当前版本；提交带稳定 `request_id` 和适用的 `expected_revision`。精确重试保留原请求标识，改变输入则使用新标识。冲突后读取并合并，不绕过版本检查。
- 公司 `data_revision` 是系统生成的经营快照标识，用于追溯和变化检测，Agent 不递增或人工维护。事件基线、报告/预测数据版本、回合 `after_revision` 和结算快照省略时由服务事务确定；回合使用本公司已选择或处理中的 `decision_id` 时可推导 `before_revision`，否则必须提供。历史基线显式提交并接受校验。更新记录仍使用该记录自己的版本。
- 保存、重选、领取后复用回执中的 `record.revision` 做下一次更新；回合可用 `decision_id` 推导选择前基线。不要仅因公司快照版本增加而重复修订事件或重新读取全部资料。
- 金额采用该公司币种的整数最小单位，保留来源、发生日期和更正关系。现金更正或冲销不抹除原记录。
- 公司文件编辑后显式同步，核对操作回执与文件摘要。合同、预测、报告和实际经营记录的状态保持明确。
- 路线变更提交新版本；预测注明基准、数据版本和假设，周报/月报注明期间与截止点。
- 模拟公司通过同一维护接口更新虚构经营数据，再按 `simulation_turn.put` 合同提交行动、叙事和后果，附相关 `research` 来源与 `calculation` 输入、方法和结果。从真实公司分支后使用新公司的独立授权，不将模拟成果写回真实主账。
- 模拟经营日期使用公司的 `simulation_date`，推进时按 `simulation.advance` 合同提交当前公司版本；日期不得倒退。发布回合的 `after_revision` 必须是当前已提交版本，达成反馈与该版本的指标、证据一致。

操作结束后读取回执并查询受影响的记录或指标。未成功提交的导入保留供修正。备份、恢复、迁移、插件安装和授权管理先按当前操作合同检查所需条件；迁移目标必须独立且为空，恢复后重新建立远程授权。

平台不运行定时 Agent、不调用模型、不代替用户批准外部经营行动。入口 Skill 不授予额外权限，具体权限由本地操作系统或部署凭据决定。
